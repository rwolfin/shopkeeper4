# Переход с Shopkeeper 3

Shopkeeper 4 не запускает код Shopkeeper 3 и не переименовывает его таблицы. Можно установить новый компонент рядом со старым на тестовой копии, но нельзя оформлять один заказ сразу через оба компонента.

1. Сделайте резервную копию БД, файлов, TV и чанков. Перенос самого MODX 2 на MODX 3 выполняется отдельно.
2. Установите Shopkeeper 4, перенесите валюты, статусы, доставку и способы оплаты через новые настройки. Назначьте чанки писем. Курсы проверьте на конкретном примере; старый формат может иметь другое направление курса.
3. По умолчанию TV цены и остатка называются `price` и `inventory`; укажите свои. Привяжите TV к шаблонам. Для отслеживания склада сохраните явные значения и проверьте движок таблицы TV.
4. Замените старые вызовы Shopkeeper3 и HTML-классы/JS обработчики новыми сниппетами либо формами из [API.md](API.md).
5. Переведите параметры товаров в JSON `sk4_options`. Старые TV и чанки не преобразуются автоматически. Значения вариантов должны иметь стабильные ID; надбавки — десятичные строки.
6. Перепишите плагины старых событий. Новые события имеют собственные имена, выполняются после фиксации операции и не служат pre-save validation hook.
7. При использовании MIGX/xPDO-пакетов реализуйте ProductProvider. Старые `className`, `packageName`, менеджер построения моделей, `getProducts` и `shk_*`-сниппеты этой версией не подменяются. Для вывода каталога можно продолжить использовать подходящий для MODX 3 инструмент.
8. Проверьте товар с параметрами, доставку, обе валюты, недостаточный остаток, повторное оформление, отмену и восстановление статуса, SMTP и права менеджера.

## Старые заказы

Автоматический перенос заказов **не включён**. Старые таблицы `shopkeeper3_orders`, `shopkeeper3_purchases`, `shopkeeper3_config` остаются нетронутыми. Исторические заказы можно оставить в архивной БД или переносить отдельным скриптом под конкретную схему и настройки магазина.

Не копируйте столбцы напрямую: в Shopkeeper 4 цена хранится целым числом копеек, количество — тысячных долей, контакты — JSON-объектом, параметры — JSON-массивом, статус и доставка имеют явные ID, запись использует `version`. Для внешнего импорта предусмотрено уникальное поле `legacy_id`; импорт исторических заказов не должен повторно отправлять письма или списывать склад. Перед разработкой импортера согласуйте валюты, часовой пояс исходных дат и трактовку старых параметров цены.

## Отличия beta1

Новая версия покрывает основные сценарии корзины и управления заказами, но не обещает полную совместимость со всеми расширениями Shopkeeper 3. В beta1 нет независимых именованных корзин внутри одного контекста, автоматического импорта старой БД, генератора моделей MIGX, встроенного платёжного шлюза и совместимости старых событий/чанков. Интерфейс менеджера и стандартная витрина русскоязычные; английский lexicon содержит название пункта меню, не полный перевод интерфейса.
